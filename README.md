# Chrome crawler

**Агент в боковой панели Chrome: языковая модель управляет открытой вкладкой, а когда кликать слишком медленно, пишет собственный скрипт.**

<p align="center">
  <img src="docs/img/hero.gif" alt="Панель Chrome crawler выполняет задачу на сайте" width="820">
</p>

Пишете задачу обычными словами («найди самый дешёвый велосипед», «отсортируй по цене», «сыграй в 2048»). Модель решает, как её выполнить, а расширение делает работу прямо в открытой вкладке: читает страницу, кликает, печатает, прокручивает. Клики и нажатия идут через Chrome DevTools Protocol, поэтому сайт видит их как настоящий ввод.

- Работает с облачными API и с **локальными моделями** (LM Studio, Ollama, llama.cpp, Jan, vLLM).
- Чистый JavaScript: без сборки и без зависимостей.
- Рискованные действия (покупка, отправка, удаление) — только после вашего подтверждения.

## Быстрый старт

1. Скачайте репозиторий (**Code → Download ZIP**) и распакуйте.
2. Откройте `chrome://extensions`, включите **«Режим разработчика»**, нажмите **«Загрузить распакованное»** и выберите папку проекта.
3. Нажмите на иконку расширения — откроется боковая панель. При первом запуске короткое обучение покажет, что где.
4. Нажмите на название модели в шапке (или на шестерёнку): выберите провайдера, вставьте ключ, выберите модель. Локальным серверам ключ не нужен.
5. Напишите задачу и нажмите Enter. Шаги видны в логе, рискованные клики панель спросит.

## Поиск товаров: велосипед на Авито

Откройте выдачу Авито и попросите, например: *«найди 5 самых дешёвых горных велосипедов, без запчастей»*. Агент собирает все объявления со страницы одним вызовом (`extract_items`), при необходимости листает дальше и отвечает списком: название-ссылка, цена справа, миниатюра. Кнопка **«Ещё»** покажет следующие результаты без повторов.

<p align="center">
  <img src="docs/img/avito-answer.png" alt="Ответ: список велосипедов с ценами, ссылками и фото" width="420">
</p>

### Как устроен поиск

Правила собраны на живых прогонах и проверены на Авито:

- **Смотрим максимум объявлений.** Модель не выбирает «сколько смотреть»: берётся до 100 позиций, сразу тремя способами разбора (JSON-LD, microdata, карточки на странице), побеждает тот, что нашёл больше.
- **Сначала сортировка, потом обрезка.** Если всё не помещается, сначала укорачиваются описания, потом убираются строки — и модель видит, сколько и каких объявлений скрыто. «Самые дешёвые» не теряются в обрезанном хвосте.
- **Описание продавца в каждой строке.** Так модель отличает «раму» и «руль» от велосипеда.
- **⚠ Подозрительно дешёвые.** Цена сильно ниже медианы получает нейтральную пометку: «проверь — запчасть или просто выгодно». Ничего не выбрасывается автоматически.
- **Ссылки всегда.** Если модель забыла формат или написала список одной строкой, панель сама разбивает его на пункты и подставляет ссылки и фото по цене и названию.
- **Оценка ответа.** «Хорошо / плохо» с комментарием; отчёты «плохо» копируются из настроек для разбора.

Подробно — в [docs/SEARCH_NOTES.md](docs/SEARCH_NOTES.md) (там же чек-лист для новых маркетплейсов: Озон, WB).

## /skript: модель пишет программу (на примере 2048)

Когда пошаговых кликов мало — игра, повторяющиеся операции, сайт со своим языком, — наберите `/` и выберите **/skript**. Модель пишет небольшую программу, вы её проверяете и запускаете, дальше она работает внутри страницы на полной скорости, **без вызовов модели между ходами**.

Пример: `/skript научись играть в 2048`.

### Вариант 1. Без фото: скрипт читает страницу

В классической 2048 поле — это обычные элементы страницы. Модель находит, где лежат плитки и счёт, и пишет скрипт, который читает поле из DOM, выбирает ход и жмёт стрелки.

### Вариант 2. С фото: игра нарисована на canvas

Если игра — просто картинка на `<canvas>` (или WebGL), в коде страницы поля нет. Тогда скрипт **смотрит на экран**: `__crawler.grid()` делит область на клетки и отдаёт их цвета, `__crawler.pixels()` — сами пиксели. Перед тем как писать код, модель может сделать снимок области (`screenshot_region`) и посмотреть на настоящие цвета и раскладку.

</p>

<p align="center">

> Снимки для `pixels`/`grid` не покидают браузер: они сразу превращаются в массивы цветов и выбрасываются.

### Что происходит со скриптом

`write_script` → статическая проверка (без сети, `eval` и переходов) → проверка синтаксиса → пробный запуск 1,2 с без ввода → **карточка с кодом, доступом и целью** → вы нажимаете **«Запустить»** → скрипт работает → модель получает итог и **оценку** → исправляет (`patch_script`) или завершает.

- **API `__crawler`**: `loop`, `key`, `click`, `drag`, `wait`, `report`, `done` — всё как настоящий ввод через CDP.
- **Цель и оценка.** Модель объявляет цель (`счёт ≥ 10000`), расширение само читает число со страницы и сравнивает каждый запуск с лучшим. Цель можно поправить на карточке.
- **Сторож.** Останавливает скрипт, если тот завесил страницу, перестал действовать или работает слишком долго, и объясняет почему.
- **Библиотека сайта.** Рабочий скрипт можно **«Сохранить для сайта»** — в следующий раз панель предложит его и запустит без модели. Сломался — **«Починить»** вернёт его модели.
- **Доступ.** Пресеты «Осторожный», «Исследователь», «Свободный» плюс отдельные переключатели. Банки, почта, платежи и менеджеры паролей закрыты всегда; необратимые действия всегда спрашиваются.

## Onshape: деталь из текста

В Onshape у скрипта самый сильный путь — родной язык САПР, **FeatureScript**. Откройте Part Studio и попросите: *«/skript сделай фланец Ø80 с 4 отверстиями М6»*. Модель пишет параметрическую фичу, расширение проверяет код (несуществующие значения перечислений, точки без единиц измерения) и создаёт фичу прямо в открытом документе через Onshape REST API — из самой вкладки, без отдельных ключей. Ошибки перестроения и число получившихся тел возвращаются модели, и она исправляет код.

## Режимы

| | Режим | Что делает |
|---|---|---|
| ✦ | **Задача** | Модель действует по шагам: смотрит страницу, выбирает действие, спрашивает перед рискованным |
| ? | **Вопрос** | Модель читает страницу и отвечает карточкой, ничего не трогая |
| ⌘ | **/skript** | Модель пишет скрипт для страницы, вы одобряете, он работает сам |
| ⌖ | **/study** | Изучить сайт под цель и сохранить стратегию для будущих задач |
| ⇄ | **Диалог** | Следующие задачи помнят контекст («теперь отсортируй», «а вторая страница?») |

**Что видит модель** (в настройках): «Структура» — DOM и текст, без скриншотов; «Изображение» — скриншот и координаты; «Вместе» — и то и другое. В режиме «Вместе» на страницах с крупным canvas/video снимок делается на каждом шаге.

**Мышление** (над полем ввода): «Быстро», «Авто», «Думать».

К задаче можно приложить картинки и текстовые файлы — 📎, вставка или перетаскивание.

## Интерфейс

<p align="center">
  <img src="docs/img/panel.png" alt="Главный экран панели: мозг, лог, поле ввода" width="380">
  &nbsp;
  <img src="docs/img/tentacles.gif" alt="Щупальца «выкачивают» элементы страницы, пока агент читает её" width="420">
</p>

- **Мозг** — «звёздная сеть» в центре панели (WebGL). Реагирует на ввод, размышление, действия, подтверждения и ошибки; засыпает после минуты простоя.
- **Щупальца** — декоративные: пока агент работает, они впиваются в элементы страницы и «выкачивают» их. Вёрстку не трогают, перед снимками экрана прячутся. Вид («Обычные», «Корни», «Трещины») и выключение — в настройках «Движение».
- **Быстрый выбор модели** — клик по названию в шапке: поиск, недавние модели (в том числе других провайдеров).
- **Палитра под сайт** — панель подстраивает цвета под открытую вкладку.

## Требования

- Chrome или другой Chromium-браузер с Side Panel API (Chrome 114+).
- Ключ облачного провайдера: Clodex, OpenAI, Anthropic (совместимый API), Google Gemini, OpenRouter, Groq, DeepSeek, Mistral, Together AI или xAI. Подойдёт любой OpenAI-совместимый сервер.
- **Или** локальный сервер: LM Studio, Ollama, llama.cpp server, Jan, vLLM.
- Желательна модель с вызовом инструментов (tool calling); для остальных есть запасной JSON-режим.
- Для режимов «Изображение»/«Вместе» и canvas-задач — модель, принимающая картинки.

## Приватность и ограничения

- Расширение использует разрешение `debugger`: пока оно подключено, Chrome показывает плашку, а вкладкой с открытыми DevTools управлять нельзя.
- Скриншоты для модели хранятся только в памяти (последний), но **отправляются вашему провайдеру модели**. На личных страницах используйте режим «Структура».
- Настройки, заметки и сохранённые скрипты лежат локально в `chrome.storage.local`.
- Интерфейс на русском.

## Для разработчиков

| Папка | Что внутри |
|---|---|
| `manifest.json`, `background.js` | Точки входа расширения |
| `panel/` | Боковая панель: `sidepanel.html/js`, цикл агента, вложения, повторы запросов, выбор модели, обучение |
| `art/` | Мозг (`art-net.js`), прежний точечный рисунок, анимации |
| `page/` | Код во вкладке: `content.js`, разбор товаров, щупальца |
| `skript/` | Режим `/skript`: политика, доступ, контракт, раннер, карточки, библиотека, Onshape |
| `docs/` | Заметки (`MOTION.md`, `SEARCH_NOTES.md`), лендинг, картинки README |

Тесты лежат рядом с модулями (`*.test.js`); все разом — `./test.sh`, один — `node <папка>/<файл>.test.js`. Это обычные Node-файлы: код страницы запускается в `vm` со строгими таймерами Chrome. Живое поведение (ввод через CDP, iframe, визуал) по-прежнему проверяется вручную.
